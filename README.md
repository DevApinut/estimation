# ระบบประมาณการค่าใช้จ่าย (Excel VBA → Web)

เว็บนี้ถอดแกนการทำงานจาก `ออกเอกสาร.xlsm` มาเป็น Next.js + Node.js/Express โดยไม่แก้ไขไฟล์ต้นฉบับ

## เริ่มใช้งาน

ต้องมี Node.js 20 ขึ้นไป จากโฟลเดอร์นี้ให้รัน:

```bash
npm install
npm run dev
```

- เว็บ: http://localhost:3000
- API: http://localhost:4000
- ตรวจสุขภาพ API: http://localhost:4000/health
- หน้าเว็บเรียก backend ผ่านเส้นทาง `/api` ของ Next.js แล้วส่งต่อไปยัง Express เพื่อลดปัญหาหน้าค้างจาก CORS หรือการเปิดเว็บด้วยชื่อโฮสต์อื่น หาก backend อยู่คนละเครื่องให้กำหนด `API_ORIGIN` ก่อนเปิด frontend

## Workflow ที่ย้ายมาแล้ว

- ข้อมูลโครงการจากชีต `หน้าหลัก`
- เลือกรายการจากหมวดค่าใช้จ่ายใน `tableexpend`
- โหมดรายการหักแบบเดิม: `1` แสดงข้อมูล, `2` หักหลัง VAT, `3` หักก่อน VAT
- VAT 7%, ยอดรวมก่อน/หลังหัก และยอดชำระสุทธิ
- กำไรขั้นต้นจากต้นทุน × อัตรากำไร
- ปุ่มกำไรขั้นต้นทำงานตาม Module2: เลือกรายการจาก `tableexpend`, จำกัด 9 แถว, สร้างเอกสารจาก `profit_template` และเลื่อนส่วนลงนามตามจำนวนรายการ
- แยก มท. (ไม่คิด VAT) และ มท.7 (คิด VAT)
- พิมพ์หน้า Summary เป็น PDF ผ่าน Print dialog และบันทึกข้อมูลประมาณการเป็น JSON

## โครงสร้าง

- `apps/web` — Next.js frontend
- `apps/api` — Express API และ calculation service
- `apps/api/src/calculation.test.ts` — regression tests สำหรับกฎ VBA สำคัญ

## หมายเหตุการย้ายระบบ

ไฟล์เดิมมี 29 ชีต, 419 สูตร และ VBA 7 โมดูลหลัก (รวมมากกว่า 5,600 บรรทัด) ส่วนการคำนวณถูกย้ายเป็น API แล้ว ส่วนงานผสาน Word bookmark/Content Control และการสร้าง PDF หลายแบบจาก template ยังต้องผูก template เอกสารที่ใช้งานจริงในรอบถัดไป; ปัจจุบันรองรับการพิมพ์ Summary และ export JSON ก่อน

## สถานะการถอดชีต: profit

- ต้นทางข้อมูล: `tableexpend`
- VBA ต้นทาง: `Module2.FillProfitTemplateFromSelection`
- Template ต้นทาง: `profit_template`
- ผลลัพธ์บนเว็บ: แท็บ `กำไรขั้นต้น` และเอกสาร A4 `profit`
- เลือกเฉพาะรายการที่ค่าเลือกเป็น `1`, มีรายละเอียด และมีอัตรากำไรไม่เป็นศูนย์
- สูตรกำไร: `ต้นทุน × อัตรากำไรขั้นต้น`
- สูตรรวมต่อรายการ: `ต้นทุน + กำไรขั้นต้น`
- เมื่อกดปุ่มสร้างกำไรขั้นต้น ระบบใช้ `profitReport.totalProfit` อัปเดตกลับไปยังรายการชื่อ “กำไรขั้นต้น” ในหน้า `tableexpend` ตาม `UpdateTotalGrossProfitInSourceSheet` ของ Module2
- ช่องยอดกำไรขั้นต้นใน `tableexpend` เป็นค่าคำนวณแบบ read-only และมีข้อความกำกับว่าได้จาก Module2
- คอลัมน์เลือกของรายการทั่วไปใช้ checkbox เพื่อเลือก/ยกเลิกได้ในคลิกเดียว (`0` = ไม่เลือก, `1` = เลือก)
- หมวดหักค่าใช้จ่ายยังใช้รายการเลือกวิธีหัก เพื่อรักษาโหมด VBA: `1` แสดงข้อมูล, `2` หักหลัง VAT และ `3` หักก่อน VAT
- รองรับสูงสุด 9 รายการตาม Module2 และแจ้งจำนวนรายการที่เกิน template
- แถวว่างไม่ถูกแสดงก่อนยอดรวม และส่วนลงนามเลื่อนตามจำนวนรายการ
- หากข้อความรายการยาวเกิน 30 ตัวอักษร จะลดขนาดฟอนต์ตามแนวทาง VBA เดิม
- หัวตารางใช้สองระดับ: ชื่อคอลัมน์และหน่วย โดยไม่ใช้สีพื้นหรือสีเน้น ใช้เฉพาะตัวอักษรและเส้นสีดำ
- ส่วนชื่องานไม่มีเส้นใต้ เพื่อไม่ให้เส้นซ้อนกับเส้นแบ่งด้านบนข้อความ `*** รายละเอียดแสดงการคิดกำไรขั้นต้น... ***`
- ตัดความสูงขั้นต่ำและระยะห่างหลังชื่องานออก เพื่อให้ส่วนชื่องานต่อกับเส้นด้านบนของหัวข้อรายละเอียดโดยไม่มีช่องว่าง
- รองรับพิมพ์ A4 และบันทึก PDF ผ่าน Print dialog ของเบราว์เซอร์

ไฟล์ที่เกี่ยวข้อง:

- `apps/web/app/page.tsx` — flow tableexpend, ปุ่มสร้างกำไรขั้นต้น และโครงเอกสาร profit
- `apps/web/app/globals.css` — layout A4 และตารางเอกสาร
- `apps/web/app/profit.css` — รูปแบบหัวตาราง profit
- `apps/api/src/calculation.ts` — business logic ของ Module2
- `apps/api/src/calculation.test.ts` — regression tests ของสูตรและข้อจำกัด 9 รายการ

## สถานะการถอดชีต: summary_report

- ต้นทางข้อมูล: `tableexpend`
- VBA ต้นทาง: `Module1.CreateSummaryFromTemplate`
- Template ต้นทาง: `summary_Template`
- ผลลัพธ์หลัก: `summary_report`, `summary_subtopic_table` และ `Customertable`
- ก่อนสร้างสรุป ระบบคำนวณ Module2 และอัปเดตยอด “กำไรขั้นต้น” กลับเข้า `tableexpend` ก่อน เพื่อให้ยอดค่าธรรมเนียมในรายงานเป็นค่าล่าสุด
- `summary_report` แสดงข้อมูลโครงการ, WBS, หมวดค่าใช้จ่าย, รายการที่เลือก, ยอดรวมแต่ละหมวด, VAT 7%, รายการหักโหมด 1/2/3, ยอดชำระ และผู้ลงนาม
- `summary_subtopic_table` แยกรายการที่คิดจากผู้ใช้ไฟและค่าใช้จ่ายที่ กฟภ.ลงทุน เพื่อใช้เป็นตารางประกอบ
- การแทนข้อความและตารางจาก `summary_report` ทำผ่านหน้า “จัดทำหนังสือ” ในเว็บแล้ว ส่วนการส่งออกกลับเป็นไฟล์ Word `.docx` โดยตรงยังเป็นงานรอบถัดไป; ปัจจุบันรองรับการพิมพ์/PDF จากตัวอย่าง A4
- เพิ่มแท็บ “จัดทำหนังสือ” สำหรับแทนที่ข้อความและตารางของหนังสืออนุมัติกับหนังสือ มท. ผ่านหน้าเว็บ โดยอ่านโครง Content Control จากไฟล์ Word ต้นฉบับ (`Topic`, `REF`, `Atach1`, `Data1`, `Data2`, `Data3`, `Data6`, `Date`, `FOR`, `Table1`, `Table4`) แล้วจัดเป็นแบบฟอร์มแก้ไขทางซ้ายและตัวอย่างกระดาษ A4 ทางขวา
- หน้าจัดทำหนังสือบันทึกข้อความแยกตามเลขคำร้องไว้ใน browser อัตโนมัติ ตารางหนังสืออนุมัติดึงจากค่าใช้จ่ายหนังสืออนุมัติ และตารางหนังสือ มท. ดึงจากตารางค่าใช้จ่ายหนังสือ มท. ที่คำนวณล่าสุด พร้อมพิมพ์/PDF เฉพาะเอกสารที่เลือก
- ปรับตัวอย่างออนไลน์จากการตรวจภาพทุกหน้าของ `เอกสาร มท ลูกค้าจัดหาหม้อแปลงเอง.docx` และ `เอกสารอนุมัติ_ลูกค้าดำเนินการเอง.docx`: แยกหนังสือหลักเป็น 2 หน้า A4 มีหัวหนังสือภายนอก/บันทึกภายใน เลขหน้าต่อเนื่อง เนื้อหา ตาราง เงื่อนไข ลายเซ็น และข้อมูลติดต่อในตำแหน่งใกล้ต้นฉบับ
- หน้าที่ 3 ของตัวอย่างหนังสือ มท. เป็นแบบลงนามงานก่อสร้างแยกจากหนังสือหลัก จึงตั้งเป็นตัวเลือก “แบบลงนามงานก่อสร้าง” และไม่พิมพ์เพิ่มโดยอัตโนมัติ
- ใช้ภาพจริงที่ฝังอยู่ใน Word ต้นฉบับสำหรับตราและชื่อการไฟฟ้าส่วนภูมิภาค, QR แจ้งหลักฐานการชำระเงิน และแบบลงนามงานก่อสร้าง แทนภาพ/กรอบจำลอง เพื่อรักษาสัดส่วนและรายละเอียดเหมือนเอกสารเดิม
- ปรับแม่แบบหนังสือสำหรับเสนอผู้บริหารให้ใช้ระยะขอบตาม Word ต้นฉบับ (บน 7.5 มม., ซ้าย/ขวา 25 มม., ล่าง 10 มม.) ตัวอักษร TH Sarabun New 14 pt ระยะบรรทัดกระชับ และเติมข้อความต้นแบบ `Data1`–`Data3` จากเอกสารจริงเป็นค่าเริ่มต้นแทนช่องว่าง
- แยกที่เก็บแบบร่างหนังสือเป็นเวอร์ชันใหม่ เพื่อไม่ให้ค่าช่องว่างจากแบบหน้าจอรุ่นก่อนทับข้อความต้นแบบสำหรับเสนออนุมัติ
- แก้ตารางค่าใช้จ่ายหนังสืออนุมัติไม่ให้ทำซ้ำทั้งชุดในหน้าที่ 2; หน้าที่ 2 เหลือส่วนเงื่อนไข การพิจารณาอนุมัติ ลายเซ็น และข้อมูลติดต่อ
- ตรวจ `ไฟล์อนุมัติ/เอกสารอนุมัติ_ลูกค้าดำเนินการเอง.pdf` ซึ่งเป็นผลลัพธ์ A4 จริง 2 หน้าและใช้เป็นภาพอ้างอิงหลัก: ค่าใช้จ่ายต่อข้ามหน้าที่รายการกำไรขั้นต้น หน้า 2 มีหัว “การไฟฟ้าส่วนภูมิภาค” ผู้ตรวจสอบ ผู้อนุมัติ ข้อมูลติดต่อ และ QR แจ้งหลักฐานการชำระเงิน; เพิ่ม QR ในตัวอย่างหนังสืออนุมัติให้ตรง PDF
- ตั้งค่าหน้ากระดาษของหนังสือเป็นซ้าย/ขวา 2.5 ซม. และบน/ล่าง 1 ซม. ทั้งบนหน้าจอและตอนพิมพ์ พร้อมวางภาพหัวโลโก้ไว้ชิดมุมซ้ายบนของพื้นที่เนื้อหา ขนาดกว้าง 4.17 ซม. × สูง 3.47 ซม.
- ตั้งข้อความทั้งหมดภายในหนังสือเป็นฟอนต์ `TH SarabunIT๙` ขนาด 16 pt ทั้งตัวอย่างบนหน้าจอและตอนพิมพ์/PDF โดยใช้ชื่อฟอนต์เดียวกับที่ตรวจพบในไฟล์ Word ต้นฉบับ
- แปลงตัวเลขที่แสดงภายในหน้าหนังสือจาก `0–9` เป็นเลขไทย `๐–๙` หลังการแสดงผล รวมถึงเลขหัวข้อ วันที่ จำนวนเงิน และเลขหน้า โดยไม่เปลี่ยนค่าตัวเลขต้นทางที่ backend ใช้คำนวณ
- เริ่มปรับเฉพาะหนังสืออนุมัติ: ส่วนหัวแบ่งเป็นแถว `จาก / ถึง` น้ำหนักปกติ และแถว `เลขที่ / วันที่` ซึ่งป้ายเป็นตัวหนาแต่ค่าข้อมูลเป็นตัวปกติ
- จัดแถว `จาก/ถึง` และ `เลขที่/วันที่` ให้ใช้คอลัมน์เดียวกันในแนวตั้ง และทำเฉพาะค่าหลังป้ายทั้ง 4 ช่องให้คลิกแล้วพิมพ์แก้บนกระดาษได้โดยตรง ค่าจะบันทึกแยกตามงาน เส้นช่วยแก้ไขไม่ติดไปใน PDF
- ปรับส่วนหัวหนังสืออนุมัติให้ `จาก/ถึง/เลขที่/วันที่` และค่าที่กรอกใช้ตัวปกติทั้งหมด ลดระยะระหว่างป้ายกับค่า และขยับคู่คอลัมน์ด้านหลังไปทางขวาเพื่อให้พื้นที่สองฝั่งสมส่วน
- ลดระยะค่าที่กรอกหลังป้ายลงอีกและขยับคอลัมน์ `ถึง/วันที่` ไปทางขวาเพิ่ม พร้อมให้ผู้ใช้ลากค่าหลังป้ายทั้ง 4 ช่องในแนวนอนบนกระดาษได้เอง ตำแหน่งที่ลากบันทึกแยกตามงานและไม่กระทบค่าข้อความ
- ปรับ `เรื่อง`, `อ้างถึง`, `สิ่งที่ส่งมาด้วย` เป็นตัวปกติ และทำค่าหลังหัวข้อให้คลิกพิมพ์หรือลากซ้าย–ขวาได้เหมือนส่วนหัว ค่าที่แก้และตำแหน่งบันทึกแยกตามงาน ช่องข้อความขยายความสูงและตัดเป็นหลายบรรทัดได้โดยไม่ทับบรรทัดถัดไป
- จัด baseline ของค่าหลัง `เรื่อง/อ้างถึง/สิ่งที่ส่งมาด้วย` ให้ตรงกับป้ายด้านหน้า โดยตัด padding และ border ที่ดันข้อความลง แล้วใช้ outline ซึ่งไม่กินพื้นที่เป็นเส้นช่วยตอนแก้ไขแทน
- ซ่อนชื่อ Content Control ภายใน เช่น `Topic`, `REF`, `Atach1`, `Data1`–`Data6` ออกจากหน้าจอจัดทำหนังสือ เหลือเฉพาะชื่อช่องภาษาไทยสำหรับผู้ใช้งาน

- `summary_report` มีเส้นบางเต็มพื้นที่ใต้ชื่องานก่อนบรรทัด WBS; ยอดรวมหมวดใช้เส้นตารางเดี่ยวเต็มแถว และยอดสำคัญใช้เส้นคู่เต็มแถว ไม่ขีดเส้นใต้เฉพาะตัวเลข
- เพิ่มระยะคั่นระหว่างยอดเงินกับหน่วย “บาท” ทุกแถว และกำหนดให้แถวรวม/แถวสำคัญใช้ตัวหนาทั้งป้าย ยอดเงิน และหน่วยตลอดทั้งแถว
- เส้นใต้ชื่องานเริ่มตั้งแต่ช่องป้าย “ชื่องาน” และต่อเนื่องไปจนสุดพื้นที่ข้อมูลด้วยระดับและความหนาเดียวกัน
- ป้าย “ชื่องาน” และค่าชื่องานใช้ความสูง ระยะภายใน และ baseline เดียวกัน จึงอยู่ในบรรทัดเดียวกัน
- ลดเส้นใน summary_report: ตัดเส้นรอบหัวข้อและยอดรวมย่อยออก เหลือเส้นแบ่งหลักกับเส้นคู่ก่อนยอดสำคัญเท่านั้น เพื่อลดความลายตา
- ป้ายยอดหลักใช้ถ้อยคำใกล้ต้นฉบับและเขียนคำเต็ม: “รวมเงินค่าใช้จ่ายคิดจากผู้ใช้ไฟ”, “ภาษีมูลค่าเพิ่ม 7 %” และ “รวมเงินค่าใช้จ่ายคิดจากผู้ใช้ไฟ รวมภาษีมูลค่าเพิ่ม”
- แถวยอดเงินแต่ละแถวมีเส้นบางคั่น ส่วนยอดรวมสำคัญมีเส้นคู่ด้านบนและด้านล่าง เพื่อให้อ่านง่ายโดยไม่ลายตา
- แถว “รวมเงิน” ของแต่ละหมวดมีเส้นใต้เต็มแถว เพื่อแยกยอดรวมออกจากรายการโดยไม่ขีดเฉพาะตัวเลข
- แถว “รวมเงินค่าใช้จ่ายคิดจากผู้ใช้ไฟ” และ “ภาษีมูลค่าเพิ่ม 7 %” ไม่มีเส้นใต้; ใช้ช่องว่างและน้ำหนักตัวอักษรแบ่งลำดับแทน
- หัวข้อหมวดมีระยะเยื้องคงที่ ส่วนเลขลำดับรายการจัดชิดขวาในคอลัมน์เดียวกันและรายละเอียดเริ่มในแนวเดียวกัน
- ใช้ตัวหนาเฉพาะแถว “รวมเงิน … บาท” ของแต่ละหมวด และแถว “รวมเงินค่าใช้จ่ายคิดจากผู้ใช้ไฟ รวมภาษีมูลค่าเพิ่ม … บาท” ทั้งแถว; แถวยอดอื่นใช้ตัวปกติ
- ในแถวรวม น้ำหนักตัวหนาครอบคลุมทั้งข้อความ “รวมเงิน”, ตัวเลขยอดเงิน และหน่วย “บาท” โดยไม่มีช่องใดถูกกฎตัวเลขปกติมาทับ

ไฟล์ที่เกี่ยวข้อง:

- `apps/api/src/calculation.ts` — โมเดลข้อมูลของ summary_report, summary_subtopic_table และ Customertable
- `apps/api/src/calculation.test.ts` — regression test ของ Module1
- `apps/web/app/page.tsx` — ปุ่มสร้างสรุปและโครงเอกสารทั้งสามชีท
- `apps/web/app/summary.css` — รูปแบบ A4 ของเอกสารสรุป

## สถานะการถอดชีต: Hotline

- Template ต้นทาง: ชีต `Hotline`
- ช่องกรอกหลัก: จำนวนวัน, อัตราต่อวัน, ระยะทางไป-กลับ และราคาน้ำมัน
- สูตรตามความหมายหัวข้อ: ค่าเบ็ดเตล็ด 5% รวมทุกรายการของหมวด 1+2, ค่าใช้จ่ายดำเนินการ 7.5% รวมหมวด 1+2+3, กำไรขั้นต้น 30% รวมทุกรายการของหมวด 1–6 และยอดรวมเทียบ `F30`
- API: `POST /api/hotline/calculate`
- เมื่อกด “คำนวณและส่งยอดกลับ” ระบบนำยอดรวมไปอัปเดตรายการ “ค่าบริการด้านฮอตไลน์” ใน `tableexpend`
- ค่าเริ่มต้นตามไฟล์ต้นฉบับให้ยอด 46,966.11 บาท
- หน้า Hotline เป็นเอกสาร A4 และแสดงค่าคำนวณแต่ละบรรทัดก่อนส่งยอดกลับ
- รายการ Hotline มี checkbox เปิด/ปิดแต่ละบรรทัด ช่องจำนวนและอัตราปล่อยว่างได้ โดยค่าว่างส่งเข้าคำนวณเป็นศูนย์
- คอลัมน์ “เป็นเงิน” คำนวณสดขณะพิมพ์ แต่ยอดจะกลับเข้า `tableexpend` เฉพาะเมื่อกดปุ่มส่งยอด
- รายละเอียด Hotline ใช้ฟอนต์ขนาดเดิม 15pt; รายการวันหยุดใช้ถ้อยคำสั้นลงเป็น “กรณีปฏิบัติงานวันหยุด หรือวันหยุดตามประกาศ กฟภ.” เพื่อให้อยู่บรรทัดเดียวโดยไม่ลดฟอนต์
- คอลัมน์แรกของ Hotline ใช้หัวข้อ “เลือก” ความกว้างคงที่ 12mm; checkbox อยู่กึ่งกลางและข้อความรายละเอียดทุกแถวเริ่มในแนวเดียวกัน
- ข้อความในหน้า Hotline ใช้สีดำทั้งหมด แม้รายการยังไม่ถูกเลือก เพื่อให้อ่านง่ายและไม่เกิดข้อความสีจาง
- หัวข้อหมวด เลขหมวด และ checkbox ใช้คอลัมน์ 12mm เดียวกัน ทำให้ checkbox ตรงกับแนวเนื้อหาของหัวข้อ
- checkbox ใช้กรอบดำมุมโค้งเล็กน้อย และแสดงพื้นดำพร้อมเครื่องหมายถูกสีขาวเมื่อเลือก
- เลขหัวข้อ Hotline 1–7 จัดชิดซ้ายและใช้ baseline เดียวกับข้อความหัวข้อ รวมถึงหัวข้อคำนวณอัตโนมัติ
- เลขหัวข้อยังอยู่คอลัมน์ซ้าย ส่วน checkbox ของรายการเริ่มตรงแนวตัวอักษรหัวข้อ เช่นตรงกับจุดเริ่มของ “ค่าใช้จ่ายของรถยนต์ที่ใช้ปฏิบัติงาน” ไม่อยู่ใต้เลขหัวข้อ
- ข้อ 3, 4 และ 7 แสดงตัวหนาทั้งเลข หัวข้อ และยอดเงิน
- มี regression test ยืนยันว่ารายการวันหยุด เครื่องมือ ที่พัก และรถยนต์ทุกบรรทัดถูกนำไปคิดในข้อ 3, 4 และ 7 ไม่ตกหล่น

ไฟล์ที่เกี่ยวข้อง:

- `apps/api/src/hotline.test.ts` — regression test เทียบยอด F30
- `apps/api/src/server.ts` — Hotline API
- `apps/web/app/page.tsx` — แบบกรอกและ workflow ส่งยอดกลับ

## ปรับหน้า “รายการประมาณการ” และการเชื่อมยอดอัตโนมัติ

- เปลี่ยนชื่อที่แสดงบนเว็บจาก `tableexpend` เป็น “รายการประมาณการ” เพื่อให้อ่านและเข้าใจง่ายขึ้น โดยยังคงชื่อชีตเดิมภายในระบบไว้เพื่อเทียบกับ Excel/VBA ได้ตรงกัน
- ออกแบบส่วนหัวหน้าใหม่ พร้อมการ์ดสรุปยอดกำไรขั้นต้นและยอดบริการด้านฮอตไลน์แบบอ่านอย่างเดียว โดยใช้แท็บด้านบนสำหรับเปลี่ยนหน้า จึงไม่มีปุ่มลัดซ้ำซ้อน
- ยอดกำไรขั้นต้นจาก Module2 จะอัปเดตกลับเข้ารายการประมาณการอัตโนมัติเมื่อข้อมูลต้นทุนหรือเปอร์เซ็นต์เปลี่ยน
- หน้า Hotline คำนวณขณะกรอกและเชื่อมยอดกลับเข้ารายการประมาณการอัตโนมัติ ไม่ต้องกดปุ่มคำนวณหรือส่งยอด
- หน้า “ค่าบริการฮอทไลน์” มีปุ่ม `พิมพ์ / บันทึก PDF` และจัดเป็นเอกสาร A4 แนวตั้งแบบเดียวกับหน้ากำไรขั้นต้นและสรุปค่าใช้จ่าย โดยซ่อนแถบเครื่องมือจาก PDF ปรับระยะขอบ ฟอนต์ ตาราง ยอดรวม หมายเหตุ และลายเซ็นให้อยู่ในหน้ากระดาษ
- ยอดรวม Hotline เชื่อมเข้ารายการรหัส `fee-hotline` หรือชื่อ “ค่าบริการด้านฮอตไลน์” โดยตรง และเลือก checkbox ของรายการให้อัตโนมัติเมื่อมียอดมากกว่าศูนย์
- หน้า “รายการประมาณการ” ใช้ตัวเลือกหมวดแบบสรุปจำนวนรายการและยอดเงิน แล้วแสดงตารางแก้ไขทีละหมวด เพื่อลดความยาวของหน้าและช่วยให้ค้นหารายการได้ง่ายขึ้น
- ปรับโครงหน้า “รายการประมาณการ” เป็นเมนูหมวดแนวตั้งด้านซ้ายและพื้นที่แก้ไขด้านขวา พร้อมเพิ่มขนาดช่องกรอกเพื่อให้อ่านง่ายขึ้น โดยคงหัวเว็บ สถิติ และตำแหน่งแท็บให้เหมือนหน้าอื่นเพื่อไม่ให้หน้ากระโดดเมื่อสลับแท็บ
- หน้าสรุปค่าใช้จ่ายแสดงยอดของรายการหักเป็นจำนวนเงินปกติโดยไม่มีเครื่องหมายลบนำหน้า แต่ยังนำยอดไปหักในสูตรคำนวณตามเดิม
- นำเครื่องหมายลบที่เคยเติมด้วย CSS หน้าเลขรายการหักออกแล้ว เพื่อให้ทั้งข้อมูลตัวเลขและรูปแบบการแสดงผลไม่มีเครื่องหมายลบซ้ำกลับมาอีก
- ถอดรายชื่อพนักงาน 10 คนจากชีตซ่อน `DB ชื่อพนักงาน` มาให้บริการผ่าน `GET /api/employees` และเปลี่ยนช่องผู้สำรวจ ผู้ประมาณการ และผู้ตรวจสอบเป็น dropdown ที่แสดงชื่อ ตำแหน่ง และเลขประจำตัว
- เพิ่มฐานข้อมูลรายชื่อแบบถาวรที่ `apps/api/data/employees.json` พร้อม API สำหรับเพิ่ม แก้ไข และลบรายชื่อ และมีส่วน “จัดการรายชื่อพนักงาน” ในหน้าข้อมูลงาน โดยยืนยันก่อนลบทุกครั้ง
- ช่องกรอกในตารางหน้า “รายการประมาณการ” ใช้ความสูงมาตรฐาน 46px เท่ากันทั้ง checkbox, dropdown, รายละเอียด, จำนวนเงิน และเปอร์เซ็นต์ โดยซ่อนข้อความย่อยใต้ช่องยอดคำนวณเพื่อรักษาแนวแถวให้สมมาตร
- หน้าข้อมูลงานแยกผู้สำรวจ ผู้ประมาณการ และผู้ตรวจสอบเป็นแถวเดียวกันในส่วน “ผู้รับผิดชอบงาน” และส่วนจัดการฐานข้อมูลพนักงานเป็นแผงพับ–กางซึ่งย่อไว้เป็นค่าเริ่มต้น
- หน้า “รายการประมาณการ” แสดง checkbox โดยไม่มีข้อความ “เลือก/เลือกแล้ว” ซ้ำในทุกแถว และเพิ่มปุ่มลบท้ายรายการพร้อมข้อความยืนยันก่อนลบ
- คืนข้อความ “เขต 3 ภาคใต้” ในหัวเอกสารสรุปค่าใช้จ่ายเป็นกลุ่มเดียวที่มองเห็นชัด และคืนข้อความรายการหักเป็น 16pt พร้อมขยายพื้นที่ข้อความเพื่อให้อยู่บรรทัดเดียวโดยไม่ย่อจนอ่านยาก
- จัดคำว่า “เขต 3 ภาคใต้” ให้อยู่ติดกัน ใช้น้ำหนักตัวอักษรปกติ และไม่มีเส้นใต้
- เพิ่ม “เขต 3 ภาคใต้” ในหัวเอกสารกำไรขั้นต้น และคืนรายการแผนกงานข้อความยาวเป็น 16pt เท่ารายการปกติ โดยขยายคอลัมน์รายละเอียดเป็น 52% เพื่อให้อยู่บรรทัดเดียวแทนการย่อฟอนต์
- ปรับข้อความรายการยาวในหน้ากำไรขั้นต้นเป็น 14.5pt แบบสัดส่วนตัวอักษรปกติ ไม่บีบหรือยืดข้อความ และคงไว้ในบรรทัดเดียวโดยไม่เปลี่ยนหัวตาราง
- ขนาดข้อความแผนกงานในหน้ากำไรขั้นต้นปรับอัตโนมัติตามความยาวเป็น 16, 15, 14.25 หรือขั้นต่ำ 13.75pt เพื่อใช้ขนาดใหญ่ที่สุดที่ยังอยู่บรรทัดเดียว โดยเปลี่ยนเฉพาะช่องรายละเอียดและไม่กระทบหัวตาราง
- เปลี่ยนชื่อแท็บ `Hotline` ที่แสดงบนเว็บเป็น “ค่าบริการฮอทไลน์” โดยคงชื่อโมดูลและ API ภายในเดิม

- แถว “ค่าบริการด้านฮอตไลน์” ในหมวดค่าธรรมเนียมใช้เส้นเน้นและล็อกช่องยอดเงินเหมือนแถว “กำไรขั้นต้น” เพราะทั้งสองยอดเชื่อมกลับจากหน้าคำนวณอัตโนมัติ
- ช่องจำนวนเงินในหน้ารายการประมาณการและช่องอัตราค่าบริการในหน้าฮอทไลน์แสดงเครื่องหมาย comma คั่นหลักพันขณะกรอก เช่น `30,693.57` โดยช่องจำนวนวัน ระยะทาง และเปอร์เซ็นต์ยังแสดงเป็นตัวเลขปกติ
- ล็อกรายการ `ค่าสมทบแรงสูง` (`fee-1`) และ `ค่าประกันการใช้ไฟ` (`mt-1`) เป็นสูตร จำนวนเควีเอ × ตัวคูณ ผู้ใช้แก้ตัวเลขสองช่องได้และระบบอัปเดตชื่อรายการกับยอดเงินอัตโนมัติ เช่น 30 × 100 = 3,000 และ 400 × 400 = 160,000; ช่องยอดเป็น read-only และปุ่มลบถูกปิดเพื่อรักษาลำดับรายการ
- แก้ช่องอัตราในหน้าฮอทไลน์ให้รักษาข้อความและตำแหน่ง cursor ระหว่างพิมพ์ โดยจัด comma เมื่อออกจากช่องแทนการจัดรูปแบบใหม่ทุกครั้งที่กดตัวเลข จึงแก้ไขค่าได้ตามปกติ
- หน้า “ค่าบริการฮอทไลน์” คงสถานะฟอร์มไว้เมื่อสลับแท็บ ทั้งค่าที่กรอกและ checkbox จะไม่ย้อนกลับเป็นค่าเริ่มต้นเมื่อกลับเข้าหน้าเดิม
- หน้ารายการประมาณการมีช่อง “ชื่อหมวดที่เลือก” ซึ่งเปลี่ยนตามหมวดที่กำลังเปิด ผู้ใช้แก้ชื่อ “ค่าใช้จ่ายที่ กฟภ.ลงทุน” หรือชื่อหมวดอื่นเป็นข้อความที่ต้องการได้ และชื่อใหม่จะส่งต่อไปหน้าสรุปกับเอกสารที่เกี่ยวข้อง
- หน้าสรุปค่าใช้จ่ายใช้เลขโครงสร้างอัตโนมัติ: หัวข้อหมวดเป็น `1.`, `2.`, `3.` และรายการย่อยเป็น `1.1`, `1.2`, `2.1` ตามหมวด โดยรายการย่อยเยื้องจากหัวข้อใหญ่ประมาณหนึ่งตัวอักษร
- แถวรวมของแต่ละหมวดใช้คำว่า “รวมเงิน” โดยไม่แสดงชุดเลขรายการ ส่วนแถว “รวมเงินค่าใช้จ่ายคิดจากผู้ใช้ไฟ” แสดงเลขหมวดที่นำมารวมแบบสั้นในวงเล็บ เช่น “(2+3)” โดยไม่มีคำว่า “รวมข้อ”

## Template หม้อแปลงและ Turnkey

- เพิ่มแท็บ “หม้อแปลง / Turnkey” จาก Template ชุด A ได้แก่ `T30-160`, `T250-315`, `T400`, `T>500` และ `Turnkey`
- ตัด Template ชุด B ที่ซ้ำออก เหลือชุด A ได้แก่ `T30-160`, `T250-315`, `T400`, `T>500` และแบบกำหนดเอง `Turnkey`
- Turnkey รองรับหลายงาน: กด `+ งาน Turnkey ใหม่` ตั้งชื่องาน เพิ่มรายการย่อย แล้วกด `บันทึกงานและส่งยอด` แต่ละงานจะถูกสร้างเป็นคนละรายการในหมวด “ค่าใช้จ่ายที่คิดจากผู้ใช้ไฟ” เพื่อส่งต่อไปหน้ากำไรขั้นต้นและสรุปค่าใช้จ่าย
- งาน Turnkey ที่บันทึกแล้วสามารถเปิดกลับมาแก้ไขหรือลบได้ เมื่อแก้ไข/ลบ ยอดในหน้ารายการประมาณการและสรุปค่าใช้จ่ายจะอัปเดตอัตโนมัติ
- งาน Turnkey ถูกเก็บในเบราว์เซอร์แยกตามเลขคำร้อง (fallback เป็นเลขแผนผัง) จึงยังอยู่เมื่อรีเฟรชหน้า และสามารถลบออกจากทั้งรายการงานและหน้ารายการประมาณการได้
- หัวเอกสาร `จ้างเหมาเบ็ดเสร็จ Turnkey` เปลี่ยนตามช่อง `ชื่องาน Turnkey` แบบทันที และใช้ชื่อเดียวกันใน PDF กับรายการที่ส่งไปหน้ารายการประมาณการ
- งาน Turnkey ที่บันทึกจะแสดงใน Dropdown `เลือก Template / งานที่บันทึก` พร้อมยอดเงิน เมื่อเลือกงานจะเปิดกลับมาแก้ไข และมีปุ่ม `ลบงานนี้` สำหรับลบทั้งงานออกจาก Dropdown รายการประมาณการ และสรุปค่าใช้จ่าย
- Template ชุด A ทั้ง `T30-160`, `T250-315`, `T400` และ `T>500` สามารถตั้งชื่องานแล้วบันทึกเป็นงานใหม่ได้เช่นเดียวกับ Turnkey งานที่บันทึกทุกชนิดอยู่ในกลุ่ม `งานที่บันทึก` ของ Dropdown และส่งยอดแยกบรรทัดไปหน้ารายการประมาณการ/สรุปค่าใช้จ่าย
- ย้ายชุด A ทั้ง 4 ขนาดออกจากกลุ่มแม่แบบถาวรและสร้างเป็น “งานที่บันทึก” ของโครงการปัจจุบันแบบครั้งเดียว แต่ละงานจึงเปิด แก้ไข และใช้ปุ่ม “ลบงานนี้” ได้เหมือนงาน Turnkey; ระบบบันทึกสถานะ migration แยกตามโครงการเพื่อไม่สร้างงานที่ผู้ใช้ลบแล้วกลับมาใหม่
- แก้ migration ชุด A ให้ตรวจทีละ Template ทุกครั้งที่โหลด: `T30-160`, `T250-315`, `T400` และ `T>500` ที่หายจากงานที่บันทึกจะถูกเติมกลับ แม้สถานะ migration เดิมถูกสร้างไว้แล้ว ส่วนงานที่ผู้ใช้กดลบจริงจะถูกเก็บในรายการ `deleted-set-a` แยกตามโครงการและไม่ถูกสร้างกลับ
- Dropdown หน้า “หม้อแปลง / Turnkey” เหลือกลุ่ม “แม่แบบเริ่มต้น” สำหรับ Turnkey และกลุ่ม “งานที่บันทึก” สำหรับชุด A กับงานที่ผู้ใช้สร้างทั้งหมด ลดความสับสนระหว่างแม่แบบที่ลบไม่ได้กับงานจริง
- ข้อความในคอลัมน์ “รายการ” ของหน้าและเอกสารพิมพ์ “หม้อแปลง / Turnkey” จัดชิดซ้ายสุดของช่อง โดยไม่กระทบแนวคอลัมน์จำนวนและยอดเงิน
- ชุด A ถือเป็นแม่แบบ Turnkey ที่เคยบันทึกไว้ใช้บ่อย ไม่ใช่ประเภทงานแยกต่างหาก ผู้ใช้เลือกแม่แบบแล้วปรับข้อมูลก่อนบันทึกเป็นงานจริงได้
- ยกเลิกช่องเลขที่เอกสารอ้างอิงแยก เหลือช่อง `หมายเหตุแหล่งราคา` เพียงช่องเดียวสำหรับพิมพ์ชื่อร้าน เลขเอกสาร หรือข้อความทั้งหมดเอง
- เพิ่มส่วน `จัดการราคาสินค้าจากใบเสนอราคา` เมื่อแก้ราคาต่อหน่วย ระบบจะอัปเดตรายการชื่อเดียวกันในแม่แบบ งานปัจจุบัน และงานที่บันทึกทั้งหมด คำนวณยอดใหม่ ส่งยอดใหม่ไปหน้ารายการประมาณการ/สรุปค่าใช้จ่าย และจดจำราคาสำหรับการเปิดเว็บครั้งถัดไป
- ช่องหมายเหตุแหล่งราคาแสดงข้อความที่ผู้ใช้พิมพ์ตรง ๆ ในเอกสารและ PDF โดยระบบไม่เติมคำว่า “ใบเสนอราคา”, “ราคาจาก” หรือข้อความนำหน้าอื่นให้อัตโนมัติ
- เพิ่มการปรับราคากลุ่มทองแดงเป็นเปอร์เซ็นต์ เช่น `5` สำหรับเพิ่ม 5% หรือ `-3` สำหรับลด 3% ครั้งเดียวจะอัปเดตสินค้าทุกรายการที่มีคำว่า “ทองแดง” ในแม่แบบ งานปัจจุบัน และงานที่บันทึกทั้งหมด พร้อมคำนวณยอดสรุปใหม่
- เพิ่มแผง `จัดการราคากลาง` แบบย่อ/ขยายเป็นส่วนหนึ่งของหน้า “หม้อแปลง / Turnkey” สามารถค้นหา เพิ่ม แก้ราคา ลบรายการ และปรับราคาทองแดงทั้งหมดเป็นเปอร์เซ็นต์ได้จากหน้าเดียว
- การลบราคากลางมีข้อความยืนยันและจะเอารายการนั้นออกจากแม่แบบ งานปัจจุบัน งานที่บันทึก และ Dropdown รายการ โดยจดจำการลบหลังรีเฟรชหน้า ส่วนการเพิ่มชื่อเดิมกลับมาจะยกเลิกสถานะลบ
- เพิ่ม `หมายเหตุกลาง` ในแผงเดียวกับราคากลาง สามารถเพิ่ม แก้ไข บันทึก และลบข้อความได้ หมายเหตุถูกเก็บไว้ในเบราว์เซอร์และนำกลับมาใช้ได้หลังรีเฟรช
- ช่องหมายเหตุของงานรองรับทั้งการเลือกคำแนะนำจากหมายเหตุกลางแบบ Dropdown และการพิมพ์ข้อความอิสระในช่องเดียว งานที่บันทึกจะเก็บสำเนาหมายเหตุของงานนั้นไว้
- ช่องชื่อรายการในหน้า “หม้อแปลง / Turnkey” รองรับทั้งการเลือกคำแนะนำจากรายการราคากลางและการพิมพ์ชื่อใหม่เองในช่องเดียว เมื่อเลือกชื่อที่มีในราคากลาง ระบบจะดึงราคาต่อหน่วยล่าสุดมาให้
- แยก template ชื่อไม่มีช่องว่างเป็น “ชุด A” และชื่อมีช่องว่างเป็น “ชุด B” เพื่อรักษาราคาและรายการที่ต่างกันตาม workbook เดิม
- ตารางใช้โครงเดียวกับ Excel ได้แก่ รายการ จำนวน หน่วยละ รวม ราคา กฟภ. และค่าแรง พร้อมคำนวณรวมพัสดุ รวมค่าแรง ค่าดำเนินการ 7.5% และรวมทั้งสิ้นผ่าน backend
- `Turnkey` เป็นแบบกำหนดเอง สามารถเพิ่ม ลบ แก้ไขรายการ จำนวน ราคาต่อหน่วย และค่าแรงได้ ส่วน template หม้อแปลงโหลดรายการตั้งต้นจาก Excel แล้วแก้ไขต่อได้
- API ที่เพิ่ม: `GET /api/work-templates` และ `POST /api/work-templates/calculate`
- รายชื่อ template ที่เคยเรียงเป็นปุ่มยาวด้านซ้ายถูกรวมเป็น dropdown “เลือก Template” ช่องเดียวด้านบน แยกกลุ่มชุด A ชุด B และกำหนดเอง
- คอลัมน์ “รายการ” ภายในตารางเป็นช่องข้อความเหมือนเซลล์ Excel ไม่ใช่ dropdown และยังแก้ไขชื่อรายการของ Turnkey หรือ template อื่นได้โดยตรง
- ปรับหน้าเอกสารเป็น A4 แนวนอนตามสัดส่วนชีต Excel: หัวชื่อแบบ ชื่องาน เลขแผนผัง ตาราง 6 คอลัมน์เส้นดำ ยอดรวม ค่าดำเนินการ 7.5% หมายเหตุ และลายเซ็น โดยไม่มีสีหรือการ์ดตกแต่งในตัวเอกสาร
- แถว `รวม`, `รวมค่าพัสดุ + ค่าแรง`, `ค่าดำเนินการ 7.5%` และ `รวมทั้งสิ้น` ต่ออยู่ใต้รายการสุดท้ายภายในกรอบตารางเดียวกัน เพื่อให้รูปแบบ PDF ต่อเนื่องเหมือนเอกสาร Excel
- รูปแบบพิมพ์ใช้กระดาษ A4 แนวนอน ระยะขอบ 8 มม. ฟอนต์ภาษาไทยที่อ่านง่าย และซ่อน Dropdown เลือก Template ปุ่ม `ลบ` และปุ่ม `เพิ่มรายการ` ทั้งหมดจาก PDF
- หน้า “หม้อแปลง / Turnkey” ใช้ฟอนต์เอกสาร `TH Sarabun New` และขนาดตัวอักษรแนวเดียวกับหน้ากำไรขั้นต้น/สรุปค่าใช้จ่าย รวมถึงบล็อกผู้สำรวจ ผู้ประมาณการ และผู้ตรวจสอบที่ใช้ขนาด ระยะบรรทัด และแนวชื่อเท่ากัน
- เพิ่มปุ่ม `พิมพ์ / บันทึก PDF` ข้าง Dropdown เลือก Template โดย PDF ใช้ A4 แนวนอนเฉพาะหน้า และซ่อนเครื่องมือแก้ไขทั้งหมด
- แก้เส้นตารางหน้า “หม้อแปลง / Turnkey” ให้ครบทุกช่อง โดยช่องกรอกจำนวน หน่วยละ และค่าแรงคงเส้นแบ่งแนวตั้ง/แนวนอน รวมทั้งปิดกรอบขวาและกรอบล่างของตารางทั้งบนหน้าจอและ PDF
- ขยายบรรทัด `ชื่องาน` และ `เลขแผนผัง` ในหน้า “หม้อแปลง / Turnkey” เป็น 18pt บนหน้าจอและ 16pt ใน PDF เพื่อให้อ่านง่ายและเด่นกว่าข้อมูลในตาราง
- แก้ PDF หน้า “หม้อแปลง / Turnkey” ที่ออกสองหน้า โดยใช้พื้นที่พิมพ์สุทธิ A4 แนวนอน 281 × 194 มม. หลังหักระยะขอบ 8 มม. และป้องกันการสร้าง page break หลังเอกสาร
- ยึดบล็อกผู้สำรวจ ผู้ประมาณการ และผู้ตรวจสอบไว้ด้านล่างของหน้า PDF หน้าแรก พร้อมกันพื้นที่ท้ายเอกสาร 32 มม. เพื่อไม่ให้รายชื่อทั้งสามถูกย้ายไปหน้าที่สอง

# การบันทึกหัวข้อค่าใช้จ่ายหนังสืออนุมัติ

- การเปิดหรือซ่อนหัวข้อ เช่น “ค่าธรรมเนียม” จะบันทึกแยกตามเลขคำร้องหรือเลขผังในเครื่องโดยอัตโนมัติ
- เมื่อเปลี่ยนแท็บแล้วกลับมาที่ “ค่าใช้จ่ายหนังสืออนุมัติ” สถานะเดิมจะยังอยู่
- หน้า “หนังสืออนุมัติ” ใช้สถานะเดียวกัน หัวข้อที่ซ่อนจะไม่กินเลขลำดับ และหัวข้อถัดไปจะเรียงเลขต่อเนื่อง
- แถบจัดระยะของหนังสืออนุมัติมีช่อง “รายการใต้หัวข้อค่าใช้จ่าย” สำหรับขยับชื่อรายการ ข้อความรวม และยอดรวมใต้ข้อ ๔.๑ เป็นต้นไปพร้อมกัน โดยไม่ทำให้คอลัมน์ยอดเงินเสียแนว
- ท้ายรายการค่าใช้จ่ายในหนังสืออนุมัติแสดงครบทั้ง “รวม”, “ภาษีมูลค่าเพิ่ม 7 %” และ “ยอดรวมที่ผู้ใช้ไฟต้องชำระ” โดยใช้ยอดเดียวกับหน้าสรุปค่าใช้จ่าย
- ตารางค่าใช้จ่ายภายในหนังสืออนุมัติใช้โครงสร้างเดียวกับหน้า “ค่าใช้จ่ายหนังสืออนุมัติ” ทั้งการแบ่งกลุ่ม ลำดับหัวข้อ แถวรวม ภาษีมูลค่าเพิ่ม และยอดรวมของแต่ละกลุ่ม
- ฟอนต์ในตารางค่าใช้จ่ายของหนังสืออนุมัติใช้ TH SarabunIT๙ ขนาด 16 พอยต์สม่ำเสมอทั้งชื่อรายการ ตัวเลข และหน่วย โดยทำตัวหนาเฉพาะหัวข้อและแถวยอดรวมสำคัญ
- เลขหัวข้อค่าใช้จ่าย เช่น ๔.๑ จัดให้อยู่ชิดกับชื่อหัวข้อ โดยไม่เปลี่ยนแนวคอลัมน์ยอดเงิน
- หนังสืออนุมัติและหนังสือ มท. บังคับแปลงตัวเลขบนกระดาษเป็นเลขไทยทุกครั้งหลังข้อมูลเปลี่ยนและก่อนสั่งพิมพ์/PDF เพื่อป้องกันเลขอารบิกกลับมาในไฟล์พิมพ์
- ค่า “เลขหัวข้อหลัก” ในหน้า “ค่าใช้จ่ายหนังสืออนุมัติ” ถูกบันทึกตามงานและเชื่อมกับตารางในหนังสืออนุมัติทันที เมื่อเปลี่ยนเลขฝั่งหนึ่ง อีกฝั่งจะใช้เลขเดียวกัน
- หน้าจัดทำหนังสือมีปุ่ม “แปลงเป็นเลขไทย” สำหรับสั่งแปลงเลขทั้งหมดบนกระดาษทันที และปุ่ม “พิมพ์ / PDF” จะสั่งแปลงซ้ำก่อนเปิดหน้าพิมพ์โดยอัตโนมัติ
- ส่วนเนื้อหาก่อนตารางในหนังสืออนุมัติแก้ไขบนกระดาษได้แบบ Word: แก้หรือลบหัวข้อใหญ่ได้ วางเคอร์เซอร์ตำแหน่งใดแล้วกด Enter เพื่อแทรกย่อหน้าได้ และเนื้อหาจะดันตารางลงโดยอัตโนมัติ โครงสร้างที่แก้ไขถูกบันทึกแยกตามงาน
- แถว “เรียน” ถูกยึดไว้ใต้ “สิ่งที่ส่งมาด้วย” โดยตรง จึงยังแสดง แก้ไข และเลื่อนตำแหน่งได้แม้ส่วนเนื้อหาด้านล่างจะเปลี่ยนเป็นตัวแก้ไขแบบ Word
- ตัวปรับระยะเยื้องของหนังสืออนุมัติมีช่อง “ข้อความใต้เรียน” สำหรับกำหนดระยะย่อหน้าของข้อความที่พิมพ์หรือแทรกในพื้นที่แบบ Word โดยไม่ขยับหัวข้อใหญ่และตารางค่าใช้จ่าย
- ข้อความทุกย่อหน้าภายในพื้นที่แก้ไขแบบ Word ใช้ TH SarabunIT๙ ขนาด 16 พอยต์ เมื่อข้อความตัดขึ้นบรรทัดใหม่ บรรทัดก่อนหน้าจะกระจายเต็มแนวแบบภาษาไทย ส่วนบรรทัดสุดท้ายและหัวข้อใหญ่ยังคงชิดซ้าย
- พื้นที่แก้ไขรักษาจำนวนช่องว่างที่ผู้ใช้เคาะไว้เพื่อดันคำลงบรรทัดถัดไป และบังคับจัดกระจายบรรทัดก่อนหน้าด้วยกฎเดียวกับย่อหน้าภาษาไทย
- ในพื้นที่แก้ไขแบบ Word ปุ่ม Enter สร้างย่อหน้าใหม่ที่รับระยะ “ข้อความใต้เรียน” ทุกครั้ง ส่วน Shift+Enter ใช้ขึ้นบรรทัดธรรมดาภายในย่อหน้าเดิม
- ระบบดักการกด Enter โดยตรง จึงกดเพียงครั้งเดียวเพื่อสร้างย่อหน้าใหม่และย้ายเคอร์เซอร์ไปยังบรรทัดที่มีระยะเยื้อง ไม่ต้องกดซ้ำสองครั้ง
- ย่อหน้าใหม่จะล้าง padding และระยะเยื้องที่สืบทอดจากย่อหน้าแม่ก่อนใช้ค่า “ข้อความใต้เรียน” จึงอยู่แนวเดียวกับย่อหน้าด้านบนและไม่เยื้องซ้ำสองชั้น
- พื้นที่แก้ไขหนังสือมีปุ่ม “เพิ่มย่อหน้า” และ “เพิ่มหัวข้อ” เพื่อแทรกบล็อกต่อจากตำแหน่งเคอร์เซอร์ได้ตามต้องการ หัวข้อเป็นทางเลือก สามารถแก้ข้อความหรือลบทิ้งได้ และปุ่มจะไม่ติดไปใน PDF
- หัวข้อในหนังสืออนุมัติใช้ตัวหนาโดยไม่มีเส้นใต้ ทั้งหัวข้อเดิมและหัวข้อที่เพิ่มจากตัวแก้ไข
- เมื่อกด Enter หลังหัวข้อ ระบบจะสร้างย่อหน้าปกติใหม่โดยไม่สืบทอด margin หรือ padding ของหัวข้อ จึงใช้ระยะ “ข้อความใต้เรียน” เพียงค่าเดียวและอยู่แนวเดียวกับย่อหน้าอื่น
- เมื่อเปิดงาน ระบบจะตรวจและแก้ย่อหน้าเก่าที่เคยถูก Enter แล้วบันทึกซ้อนอยู่ภายในหัวข้อ โดยย้ายออกมาเป็นย่อหน้าปกติ ล้าง style ที่ติดมา และบันทึกโครงสร้างที่แก้แล้วกลับให้อัตโนมัติ
- ตัวจัดหัวข้อย่อยตรวจเลขข้อที่ถูกบันทึกติดกัน เช่น ๑.๑…๑.๒…๑.๓ แล้วแยกกลับเป็นคนละบรรทัดอัตโนมัติ ทำให้เลขและเนื้อหาของข้อ ๑.๓ ใช้ระยะเดียวกับข้ออื่น
- ตัวจัดหัวข้อย่อยจะไม่ประมวลผลซ้ำเมื่อแยกแถวสำเร็จแล้ว ป้องกันเลขข้อและข้อความถูกแยกเป็นคนละบรรทัดในโหมดพัฒนา
- ย่อหน้าที่มีข้อย่อย ๑.๑–๑.๔ จะไม่รับคลาสย่อหน้าที่ผู้ใช้เพิ่ม แต่ใช้ hanging indent เฉพาะของหัวข้อย่อย ทำให้บรรทัดต่อเนื่องเริ่มตรงกับข้อความหลังเลขข้อ ไม่หลุดกลับไปขอบซ้าย
- ย่อหน้าที่ผู้ใช้เพิ่มด้วย Enter แล้วขึ้นต้นด้วยเลขหัวข้อย่อย เช่น ๑.๓ จะถูกตรวจพบและเปลี่ยนเป็นแถวหัวข้อย่อยอัตโนมัติ จึงไม่ถูกเยื้องแบบย่อหน้าทั่วไปจนไปอยู่กลางหน้า
- สามารถวางเคอร์เซอร์ในย่อหน้าใดแล้วกำหนด “ย่อหน้าปัจจุบัน” เป็นมิลลิเมตร จากนั้นกด “ใช้ระยะนี้” เพื่อเปลี่ยนเฉพาะย่อหน้านั้น หรือกด “คืนค่า” เพื่อกลับค่ากลาง การตั้งค่านี้ใช้เฉพาะพื้นที่เนื้อหาและไม่กระทบตารางค่าใช้จ่าย
- ปุ่ม “ตัวหนา” ใช้กับข้อความที่เลือก หรือเปิดโหมดตัวหนาจากตำแหน่งเคอร์เซอร์เพื่อพิมพ์หัวข้อเองได้ โดยรูปแบบจะถูกบันทึกไปพร้อมเนื้อหาและไม่กระทบตาราง
- ยกเลิกตัวปรับระยะรวม “บรรทัดแรกของย่อหน้า”, “ข้อความใต้เรียน” และ “หัวข้อ” เหลือชุด “ย่อหน้าปัจจุบัน” ชุดเดียวบนแถบเหนือเนื้อหา วางเคอร์เซอร์แล้วกดปรับเพื่อเปลี่ยนเฉพาะย่อหน้านั้น
- แถบจัดข้อความเหนือหนังสือมีคำสั่ง หนา บาง เอียง ขีดเส้นใต้ เพิ่ม/ลดขนาด และเลือกสี ใช้กับข้อความที่เลือกหรือรูปแบบการพิมพ์จากตำแหน่งเคอร์เซอร์ โดยไม่ครอบคลุมตารางค่าใช้จ่าย
- เมื่อกด Enter ย่อหน้าใหม่จะคัดลอกค่า “ย่อหน้าปัจจุบัน” จากย่อหน้าต้นทาง จึงเริ่มตรงแนวเดิมแทนการย้อนกลับไปใช้ค่ากลาง 25 มม.
- การวางข้อความจาก Microsoft Word จะรับเฉพาะข้อความธรรมดาและการขึ้นย่อหน้า ไม่รับแท็ก `w:sdt`, style `mso-*`, AngsanaUPC หรือ span ซ้อนจาก Word ส่วนข้อมูลเก่าที่ติดโค้ด Word จะถูกล้างอัตโนมัติเมื่อเปิดงาน โดยรักษาค่าระยะย่อหน้าที่ตั้งในระบบไว้
- ใต้ตารางสรุปรายการค่าใช้จ่ายของหนังสืออนุมัติมีพื้นที่แก้ไขอีกหนึ่งกรอบ รูปแบบเดียวกับพื้นที่ใต้ “เรียน” สำหรับพิมพ์ข้อความหรือเพิ่มย่อหน้า ข้อมูลบันทึกแยกตามงาน และกรอบ/ข้อความตัวอย่างไม่ติดไปใน PDF
- Toolbar ตรวจจับพื้นที่แก้ไขที่มีเคอร์เซอร์ล่าสุดทั้งกรอบใต้ “เรียน” และกรอบใต้ตาราง เครื่องมือรูปแบบและปรับย่อหน้าจึงใช้กับกรอบใดก็ได้ และบันทึกกลับไปยังพื้นที่ที่แก้ไขถูกต้อง
- กล่องใต้ตารางมีคลัง “แม่แบบกำหนดทรัพย์สิน” พร้อมแม่แบบมาตรฐานข้อ ๕.๑–๕.๔ ผู้ใช้เลือกดึงมาใช้ บันทึกเนื้อหาปัจจุบันเป็นแม่แบบใหม่ อัปเดต หรือลบแม่แบบที่สร้างเองได้ แม่แบบใช้ร่วมกันทุกงาน แต่ข้อความที่ดึงมาแก้ในเอกสารยังบันทึกแยกตามงาน
- หน้าหนังสืออนุมัติซ่อนชุดช่องข้อมูลซ้ำทางซ้าย ได้แก่ สิ่งที่ส่งมาด้วย ที่มาและรายละเอียดงาน รายละเอียดประกอบการพิจารณา เงื่อนไขและข้อกำหนด รหัสผู้จัดทำ และสถานะตาราง เนื่องจากแก้บนกระดาษและผ่านแม่แบบได้โดยตรงแล้ว โดยยังคงโหมดลากและตัวปรับตาราง
- แถบเลือกและจัดการแม่แบบกำหนดทรัพย์สินถูกย้ายออกนอกกระดาษ ลอยอยู่ใต้ Toolbar และติดตามขณะเลื่อน หลังดึงแม่แบบแล้วสามารถเลือกข้อความในกล่องล่างและแก้รูปแบบผ่าน Toolbar ชุดเดียวกันได้
- การปรับย่อหน้าในกล่องแม่แบบล่างจะตรวจ `<div>` หรือ `<p>` ที่อยู่ใต้เคอร์เซอร์จริง ไม่ใส่ค่าที่กรอบรวม จึงปรับระยะเฉพาะย่อหน้าที่เลือกและแสดงค่าปัจจุบันของย่อหน้านั้นบน Toolbar
- ค่าระยะเฉพาะย่อหน้าในกล่องล่างมีลำดับ CSS สูงกว่าค่ากลางเดิม จึงขยับจริงเมื่อกด “ปรับย่อหน้า” และยังไม่ส่งผลไปยังตาราง
- แถบเลือกและจัดการแม่แบบกำหนดทรัพย์สินย้ายไปลอยฝั่งซ้ายของหน้าจอ ส่วน Toolbar จัดข้อความอยู่ฝั่งขวา ทั้งสองแถบติดตามเมื่อเลื่อนและไม่แสดงใน PDF
- เมื่อกลับจากแท็บอื่นมายังหน้าจัดทำหนังสือ ระบบจะโหลด HTML ที่ผู้ใช้แก้และบันทึกล่าสุดกลับเข้าพื้นที่ใต้ “เรียน” ก่อนแสดง ป้องกัน React นำข้อความหรือระยะ `25mm` ชุดเก่ามาทับการแก้ไข
- แผงแม่แบบกำหนดทรัพย์สินอยู่ใน sidebar ฝั่งซ้าย ใต้แผง “ปรับตำแหน่งตารางค่าใช้จ่าย” โดยตรง ไม่ลอยทับหน้าจอ และเลื่อนภายใน sidebar เดียวกัน
- กฎจัดแนวหัวข้อย่อย ๑.๑–๑.๔ จะทำงานเฉพาะย่อหน้าที่มีเลขข้อจริง ย่อหน้าข้อความทั่วไปบรรทัดที่สองจะไม่ถูกเพิ่ม padding หรือล้าง text-indent จึงใช้ค่า 25 มม. เท่ากับย่อหน้าแรก และระบบล้าง `text-indent`/`white-space` ที่ติดมากับ span เก่า
- แม่แบบกำหนดทรัพย์สินทุกชุดมีชื่อแสดงใน dropdown ตอนบันทึกแม่แบบใหม่ระบบจะถามชื่อ และปุ่ม “อัปเดตแม่แบบ” สามารถเปลี่ยนชื่อพร้อมบันทึกเนื้อหาล่าสุดได้ เพื่อให้จำและเลือกใช้งานแต่ละกรณีได้ง่าย
- แผงแม่แบบใน sidebar ใช้ React Portal แทนการย้าย DOM ด้วยตนเอง จึงมีเพียงชุดเดียวและไม่ถูกสร้างซ้ำเมื่อสลับแท็บหรือเมื่อหน้าหนังสือเรนเดอร์ใหม่
- เพิ่มคลัง “แม่แบบข้อความใต้เรียน” สำหรับพื้นที่เนื้อหากล่องบน สามารถตั้งชื่อ ดึงมาใช้ บันทึกใหม่ อัปเดต และลบได้เหมือนแม่แบบกำหนดทรัพย์สิน โดย sidebar เรียงแม่แบบข้อความใต้เรียนไว้ก่อน และแม่แบบกำหนดทรัพย์สินไว้ถัดลงมาตามลำดับกล่องบนกระดาษ
- เพิ่มกล่อง “ข้อความเพิ่มเติมใต้เรียน” แยกอีกหนึ่งกล่องก่อนตาราง พร้อมคลังแม่แบบของตัวเอง Sidebar เรียงแม่แบบข้อความใต้เรียน → แม่แบบข้อความเพิ่มเติมใต้เรียน → แม่แบบกำหนดทรัพย์สิน และ Toolbar ใช้กับกล่องใหม่นี้ได้ด้วย
- แม่แบบทั้งสามกลุ่มมีปุ่ม “ซ่อนกล่อง/แสดงกล่อง” แยกกัน สถานะบันทึกตามงาน เมื่อซ่อนแล้วกล่องเนื้อหาและพื้นที่ของกล่องจะหายไป ทำให้บรรทัดหรือส่วนถัดไปเลื่อนขึ้นมาชนทันที
- กล่องข้อความที่มีเคอร์เซอร์จะไฮไลต์พื้นหลังเหลืองอ่อนพร้อมกรอบสีทอง เพื่อบอกว่ากำลังแก้กล่องใด เมื่อคลิกออกสีจะหาย และสีไฮไลต์ไม่ติดไปใน PDF
- แผงแม่แบบถูกวางตามตำแหน่งคงที่ตั้งแต่สร้าง โดยไม่ย้าย DOM หรือจัดเรียงซ้ำระหว่างใช้งาน เพื่อป้องกันกล่องสลับตำแหน่งหรือกระโดดเมื่อเลือกกล่องและใช้ Toolbox
- แผงแม่แบบทั้งสามใช้ container กลางเดียวกันและล็อกลำดับด้วย CSS เป็น ข้อความใต้เรียน → ข้อความเพิ่มเติมใต้เรียน → กำหนดทรัพย์สิน จึงไม่ขึ้นกับลำดับการโหลดหรือ re-render และไม่มีการย้ายแผงภายหลัง
- เมื่อชี้เมาส์ คลิก หรือใช้งานตัวเลือกในแผงแม่แบบ กล่องข้อความที่เชื่อมกับแม่แบบนั้นจะเรืองสีเหลืองอ่อน เพื่อบอกความสัมพันธ์ของแต่ละชุดอย่างชัดเจน และเอฟเฟกต์จะไม่ติดไปในงานพิมพ์/PDF
- Toolbox ด้านบนเป็นเครื่องมือกลางของกล่องข้อความทั้งหมดในหนังสืออนุมัติ โดยตรวจกล่องและย่อหน้าจากตำแหน่งเคอร์เซอร์อัตโนมัติ จึงใช้จัดตัวหนา บาง เอียง ขีดเส้นใต้ ขนาด สี และระยะย่อหน้าได้กับทั้งกล่องเดิมและกล่องที่เพิ่มใหม่
- กล่องข้อความที่วางต่อกันใช้ระยะบน–ล่างเป็นศูนย์และลดความสูงขั้นต่ำเหลือหนึ่งบรรทัด ทำให้เนื้อหาต่อเนื่องกันโดยไม่มีช่องว่างจากกรอบ แต่กล่องว่างยังมีพื้นที่หนึ่งบรรทัดสำหรับคลิกและพิมพ์
- รูปแบบพื้นฐาน 16 pt และตัวตรงกำหนดไว้ที่ระดับกล่องเท่านั้น ไม่บังคับทับข้อความย่อย ทำให้ Toolbox สามารถใช้ตัวเอียง เพิ่ม–ลดขนาด และเปลี่ยนสีเฉพาะข้อความที่เลือกได้จริง; คำสั่ง “บาง” บังคับถอดตัวหนาจากช่วงที่เลือก
- ปุ่ม A−/A+ อ่านขนาดจริงจากข้อความที่เลือกแล้วลดหรือเพิ่มครั้งละ 1 pt (ช่วง 8–48 pt) แทนคำสั่งเพิ่ม–ลดขนาดแบบเดิมของเบราว์เซอร์ เพื่อให้ทำงานแน่นอนในทุกกล่องข้อความ
- ก่อนใช้ A−/A+ ระบบจะปิดโหมด `styleWithCSS` ที่อาจค้างจากคำสั่งตัวบาง เพื่อไม่ให้เบราว์เซอร์สร้างค่า `xxx-large`; ขนาดปัจจุบันถูกจำกัดให้อยู่ในช่วงที่รองรับก่อนคำนวณ จึงเพิ่มและลดกลับได้ตามลำดับ
- Toolbox แสดงขนาดตัวอักษรปัจจุบันเป็นหน่วย pt ระหว่างปุ่มขนาดและตัวปรับย่อหน้า โดยอัปเดตตามตำแหน่งเคอร์เซอร์ ข้อความที่เลือก และทันทีหลังใช้ A−/A+
- บรรทัด “ยอดรวมที่ผู้ใช้ไฟต้องชำระ รวมภาษีมูลค่าเพิ่ม 7 %” จะแสดงเฉพาะเมื่อมีค่าใช้จ่ายมากกว่าหนึ่งกลุ่ม (ผู้ใช้ไฟ/มท./มท.7) ที่ต้องนำมารวมกัน หากมีเพียงกลุ่มเดียวจะใช้ยอดรวมของกลุ่มนั้นและไม่แสดงยอดซ้ำ
- นำปุ่ม “+ ย่อหน้า” และ “+ หัวข้อ” ที่ซ้อนอยู่บนกรอบแก้ไขออก ใช้ Enter เพื่อเพิ่มย่อหน้าและใช้เครื่องมือหนา/บางเพื่อทำหัวข้อเองแทน
- เครื่องมือจัดข้อความและระยะย่อหน้าจัดเป็นแถบ Toolbar แยกจากกรอบเนื้อหา และใช้ตำแหน่ง sticky เพื่อให้ติดด้านบนขณะเลื่อนอ่านหรือแก้หนังสือ โดยแถบนี้ไม่แสดงใน PDF
- Toolbar จัดข้อความถูกย้ายออกจากพื้นที่กระดาษ ใช้ตำแหน่งลอยติดขอบบนขวาของหน้าจอและคงตำแหน่งขณะเลื่อน จึงไม่กินพื้นที่หรือดันเนื้อหาในหนังสือ
